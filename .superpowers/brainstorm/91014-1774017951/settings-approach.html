Architecture

Single settings page with 4 tabs, SQLite persistence, React context for live UI settings

A

Approach A: Single Settings Page (Recommended)

One /settings route with tabs. useSettings() React context. SQLite key-value store. Components read from context. Simple, clean, all in one place.

B

Approach B: Distributed Gear Icons

Each page gets a gear icon opening a settings drawer for that page's constants. Contextual but scattered — hard to find all settings.

C

Approach C: Central + Inline Overrides

Settings page for defaults plus per-component overrides (right-click to customize). Power-user friendly but complex for v1.
